## 1. CSS architecture change: rem + `--sb-scale` (do this first)

The theme currently sizes everything in `vw`, which breaks in portrait and
can't be scaled. Replace with a **vmin-derived rem base** so one number
controls the whole UI:

```css
:root { --sb-scale: 1; }
html   { font-size: calc(1vmin * var(--sb-scale)); }
```

- Convert **every** `vw`/`vh` font-size, gap and padding in
  `themes/classic/theme.css` to `rem` using the tables in §5.
  (Landscape 16:9 conversion used: `1vw ≈ 1.78vmin`, then rounded to
  designed values — use the table values, not the formula.)
- Layout containers keep `vw`/`vh`/`%` where they describe the viewport
  (e.g. `#screen-root` padding `4vh 4vw`, `max-width: 70vw` blocks).
- Because the base is `vmin`, text is the same physical size in landscape
  and portrait on the same panel; only the layout restacks (§4).

### Config + debug param

- Add to config defaults (`config.js`): `display: { scale: 1.0 }`
  (valid 0.5–2.0; clamp on read). Already documented in CONFIG-SCHEMA.md.
- Add debug param `?scale=` (e.g. `?scale=1.3`) in `debugParams()` —
  overrides `display.scale` for the view only, never persisted (same
  pattern as `?zone=`).
- `main.js` applies it once per config (re)load:
  `document.documentElement.style.setProperty('--sb-scale', scale)`.

## 2. NORMAL screen: hero row with next azan + iqamah

People read two things from across the hall: **next salah time** and its
**iqamah time**. Both become first-class, equal to the clock.

### Engine: expose the next iqamah

In `engine.js` `buildCycle()`, attach `iqamahTime` to **every** segment's
meta (currently only BETWEEN has it):

```js
const meta = Object.assign({ iqamahTime: iqamahDate }, extraMeta || {});
```

Same in `buildJumuahCycle()`: `iqamahTime = khutbahEnd` (the IQAMAH segment
start). Then extend `azanEvents()` to carry it:

```js
.map(s => ({ prayer: s.prayer, jumuah: !!(s.meta && s.meta.jumuah),
             time: s.start, iqamahTime: s.meta.iqamahTime || null }))
```

`nextAzan()` now gives ui.js both times with no extra computation.

### Layout (landscape)

Replace the current `clock-big` + `next-prayer` rows with a two-card hero
row (`.hero-row`, flex, `gap: 2rem`):

```
┌──────────────────────────────┬───────────────────────────┐
│                              │  NEXT PRAYER      (label)  │
│        10:02:29 AM           │  ஜும்ஆ            (name)   │
│        (clock card)          │  அதான் 1:00 PM │ இகாமத் 1:35 PM │
│                              │  02:57:30    (countdown)   │
└──────────────────────────────┴───────────────────────────┘
```

- Clock card: `flex: 1.2`; next card: `flex: 1`. Both use the existing
  `.card` treatment (elevated bg, border, radius), content centered.
- Next card internals: label row → name → a two-column times row
  (azan | iqamah, divided by a `1px solid var(--sb-border)` vertical rule)
  → countdown to azan.
- Azan time = `nextAzan.time`, iqamah time = `nextAzan.iqamahTime`,
  both via `SBEngine.formatTime()`. Countdown = existing `fmtCountdown`.
- Prayer name uses existing `prayerLabel()` (handles Jumu'ah).
- The times row is the point of this milestone — the two wall-clock times
  are the **largest text in the card** (see sizes, §5).

### Kill all small text

After §5's table there is **no text below 2.2rem anywhere on any state
screen** (≈24px on a 1080p panel, ≈17px on 1366×768 at scale 1 — and the
admin can raise `display.scale`). Sizes below 2.2rem in today's CSS are
all listed with new values in §5.

### Jumu'ah banner (localization fix, same element)

`renderNormal()` currently hardcodes English `"today"`. Rebuild it from
pack labels only:

```
{labels.jumuahToday} · {labels.bayan} {config.jumuah.bayan} · {labels.azan} {config.jumuah.azan}
```

(omit the bayan part when `config.jumuah.bayan` is null).

## 3. Full i18n — no hardcoded English anywhere

Primary language = `config.masjid.languages[0]` (unchanged mechanism).
Remove every hardcoded English string from `engine.js`/`ui.js`:

1. **Gregorian date** — delete `gregorianText()`'s English arrays. Use
   `Intl.DateTimeFormat(locale, { weekday:'long', day:'numeric',
   month:'long', year:'numeric' })` with this locale map (add to ui.js):
   `{ en: 'en-GB', ta: 'ta-LK', si: 'si-LK' }` (fallback `'en-GB'`).
2. **Hijri month names** — `engine.js` `hijriInfo()` currently uses an
   English `HIJRI_MONTHS` array and appends `"AH"`. Change `hijriInfo` to
   accept the active content pack (or month-name array + era label) and
   build: `` `${day} ${pack.hijriMonths[monNum-1]} ${year} ${labels.hijriEra}` ``.
   Keep the English array as the fallback when a pack lacks
   `hijriMonths`. All three packs already contain `hijriMonths[12]` and
   `labels.hijriEra` — do not edit the packs.
3. **Numerals stay Western** (0-9) in all languages — standard in Sri
   Lankan Tamil/Sinhala print. Do not use Intl numbering systems for
   times/countdowns; only the Intl Gregorian date may render as the
   locale defaults.
4. **`?lang=` debug param** — add to `debugParams()`. When present and a
   pack for it exists, treat it as the primary language for the view
   (reorder, don't replace: `[lang, ...others]`) — never persisted.
   Language is otherwise changed via config
   (`masjid.languages`, admin panel in M2).

`ta.json`, `si.json`, `en.json` are complete and structurally identical —
if a key is ever missing at runtime, fall back to the `en` pack value
(current `label()` fallback returns the raw key; change it to look up
`en` first, then raw key).

## 4. Responsive: 1366×768, 1920×1080, landscape + portrait

Target panels: 1366×768 and 1920×1080, each mounted 16:9 **or** 9:16
(768×1366, 1080×1920). The rem/vmin base (§1) already equalizes text
size; this section is only about layout restacking.

Add at the end of theme.css:

```css
@media (orientation: portrait) { ... }
```

Portrait overrides (NORMAL):

- `.topbar` → `flex-direction: column; align-items: center;
  text-align: center;` (dates centered under the masjid name).
- `.hero-row` → `flex-direction: column;` (clock card above next card,
  both full width).
- `.timetable-strip` → `display: grid; grid-template-columns: 1fr 1fr;`
  (6 cells become a 2×3 grid); each `.tt-cell` gets
  `padding: 1.2rem 0;` and rows separated by
  `border-top: 1px solid var(--sb-border)` from the second row on.
- All `max-width: 70vw` blocks (azan/between/dua cards) → `max-width: 88vw`.

Other state screens are single centered columns already — they need no
structural portrait changes, only the rem conversion.

Landscape stays structurally as today (topbar / hero row / banners /
timetable strip / rotation card), with `.screen--normal`
`justify-content: space-between` unchanged.

## 6. Acceptance criteria

(`?t=`, `?state=`, `?zone=`, and the new `?scale=`, `?lang=`), using
devtools responsive mode at 1366×768, 1920×1080, 768×1366, 1080×1920.

- [ ] NORMAL shows clock + next-block hero; azan AND iqamah wall-clock
      times are the dominant text of the next-block, with countdown
- [ ] Next iqamah time matches the BETWEEN screen's countdown target for
      every prayer incl. Friday Jumu'ah (`?t=` walk a full Thursday and
      Friday)
- [ ] No text below 2.2rem on any state screen; board is readable in a
      browser zoomed to simulate 10 m viewing
- [ ] `?scale=0.7` and `?scale=1.5` scale every screen uniformly with no
      overflow/clipping at all four test resolutions;
      `display.scale` in localStorage config does the same persistently
- [ ] All four resolutions render correctly for a full `?t=` day walk —
      portrait restacks (stacked hero, 2×3 timetable), landscape unchanged
- [ ] `?lang=ta`, `?lang=si`, `?lang=en` each render the ENTIRE UI in that
      language — including Gregorian date, Hijri month + era, Jumu'ah
      banner; zero hardcoded English visible in ta/si
- [ ] Missing pack key falls back to the `en` value, never a raw key
- [ ] 24h+ run still leak-free (no new per-tick allocations of
      Intl.DateTimeFormat — cache formatters per language)
